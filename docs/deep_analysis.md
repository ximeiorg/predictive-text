# Small 模型性能瓶颈深度分析

## 问题总结

### 症状
```
Small 模型: Loss 4.6, PPL 100, 评分 22/100
Base 模型:  Loss 3.8, PPL 45, 评分 36/100
```

### 根本原因

**1. Embedding 参数占比过高 (主要问题)**

| 模型 | Embedding | Transformer | 问题 |
|-----|-----------|-------------|------|
| Small (原) | **74%** | 26% | ❌ 学习能力不足 |
| Small (新) | 55% | 45% | ✅ 平衡 |
| Base | 39% | 61% | ✅ 合理 |

**原因**: 词表 8000，Small 的 hidden_dim=256 太小，导致 Embedding 占用太多参数。

**2. 数据量相对不足**

```
Tokens/参数 = 7
建议值     > 100

数据量只有建议值的 7%
```

---

## 已实施的解决方案

### ✅ 调整模型配置

**修改** (`src/config.py`):

```python
@classmethod
def small(cls) -> "ModelConfig":
    return cls(
        hidden_dim=320,      # 256 → 320 (+25%)
        num_layers=6,        # 4 → 6 (+50%)
        ffn_dim=1024,        # 512 → 1024 (+100%)
        ...
    )
```

**效果**:

| 指标 | 原 Small | 新 Small | Base |
|-----|---------|---------|------|
| 总参数 | 4.2M | 14.1M | 23M |
| Embedding 占比 | 74% | **55%** | 39% |
| Transformer 占比 | 26% | **45%** | 61% |
| 学习能力 | 弱 | **中等** | 强 |

**预期性能改善**:
```
困惑度: 100 → 45-55 (改善 45-55%)
评分:   22   → 35-40
```

## 为什么之前的优化无效？

**尝试过的优化**:
- 学习率: 3e-4 → 5e-4
- Epochs: 10 → 25
- 梯度裁剪: 1.0 → 0.5

**为什么效果不明显**:
- 这些是**训练技巧**，不改变模型容量
- 74% 参数在 Embedding，学习能力有限
- 调参无法弥补架构问题

**类比**:
- 车辆引擎太小 (Transformer 参数少)
- 调整驾驶技巧 (训练参数) 无法提速
- 需要换更大引擎 (增加模型容量)
